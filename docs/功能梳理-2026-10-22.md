## 0. 一句话定位

这个项目做的是**给 SuperFW（GBA 烧录卡 SuperCard 的第三方固件）换肤**。它由两条并列的产品线加一个共用固件底座组成：

| 路线 | 做法 | 用户体验 | 现状 |
|---|---|---|---|
| **A 烘焙注入** | 把背景图/配色/图标直接烤进**官方固件二进制** | 每换一次皮肤要重刷一次固件，受固件空白区容量限制 | v0.01~v0.16 的主路线，现降级为兜底方案，代码完整可用 |
| **B SD 卡主题** | 编译一个会读 `/.superfw/theme.bin` 的固件；皮肤放 SD 卡 | **刷一次固件，之后只换卡上的一个文件** | v0.17 起的**主路线**，v0.30 是当前发布版 |

两条线共用同一套「6 套主题 × 6 个颜色角色 + 6 套图标 + 壁纸/页面图」的数据模型，格式定义在 `app/sdtheme.py` 与 `fw/src/sdtheme.c` 两侧，靠自检脚本对照常量防漂移。

## 2. 模块 A：SD 卡主题编辑器（主产品）

### 2.1 主题包读写层 —— `app/sdtheme.py`

纯数据层，不依赖 tkinter，可被命令行/自检直接调用。

| 功能 | 作用 | 核心代码 |
|---|---|---|
| 打包 | 把 6 套配色 + 6 套图标 + 壁纸/页面图序列化成 `theme.bin`，**自动选最小可行版本** | `pack()`（L218） |
| 解析 | 读任意版本的 `theme.bin`，按「文件总长 − 尾段长度」反推基础版本 | `parse()`（L389） |
| 版本判定 | `_BASE_BY_SIZE` 长度表；**绝不能用 `b[8] >= 4` 猜布局** | `_BASE_BY_SIZE`（L111） |
| 归一化 | 把「单图 / 6 张列表 / 6×7 嵌套」统一成扁平结构，避免上游传参形态不一致 | `_norm_wall_list`、`_flatten_slots` |
| 色彩换算 | RGB888 ↔ RGB555 | `color555()` / `rgb555()` |
| 页面命名 | 七个标签页的中文名（最近/文件/烧录/设置/页面设置/工具/关于） | `PAGE_NAMES`（L125） |

支持的格式版本（尺寸见 `docs/FORMAT.md`）：

| 版本 | 新增能力 | 全满尺寸 |
|---|---|---|
| v1 | 6 套配色 + 6 套图标 + **一张**共用壁纸 | 61,680 / 26,680（无壁纸） |
| v2 | 每套各一张默认壁纸 | 236,680 |
| v3 | 7 张页面图（按标签页覆盖默认图） | 481,680 |
| v4 | 每套 × 每页独立页面图（42 位掩码） | 1,951,688 |
| v5 | +6 套 × 3 个整屏色（载入底/进度条/游戏内菜单底），尾巴 36 B | — |
| v6 | +31×7 Logo 索引与 3 色调色板，尾巴 259 B | — |

## 3. 模块 B：固件侧 SD 主题加载 —— `fw/src/sdtheme.c`

这是路线 B 的另一半。核心设计是**内存里永远只放一套**（约 40 KB），开机只读当前套，切换时才现场读卡。

| 功能 | 作用 | 入口 |
|---|---|---|
| 装载 | 打开 `theme.bin`，覆盖配色/图标/壁纸 | `sdtheme_load(thnum)` |
| 路径回退 | `/.superfw/theme.bin` → `/superfw/theme.bin` → `/theme.bin` | 同上 |
| 自动生成 | 卡上没文件时，把内置皮肤写出一份 26,680 B 的 `theme.bin`，让用户有个起点 | `sdtheme_save_default()` |
| 判断「文件不存在」 | 区分「没文件」和「文件坏了」，前者才自动生成 | `sdtheme_missing()` |
| 切套 | 换套时图标与壁纸一起换 | `sdtheme_apply_theme()` |
| 切页 | 页面图优先 > 当前套默认图 > BG 纯色；只有「要显示的段变了」才读卡 | `sdtheme_set_page()` |
| 每帧铺壁纸 | CPU 32 位 `stmia` 写入当前帧 `frame+0xF00` 一页 | `sdtheme_render_wall()` |
| 载入画面铺图 | 游戏 ROM 读卡期间复用同一份缓存，不再读卡 | `sdtheme_render_wall_at()` |
| 缓存保护 | 写 NOR / 生成补丁会踩 SDRAM，标记失效后按需重读 | `sdtheme_invalidate()` + `sdtheme_poll()` |
| 诊断 | `SDTHEME_DIAG=1` 构建时在屏幕四行显示装载结果 | `sdtheme_diag_text()` |
| 整屏色 | 把 v5 的三色写进 `MEM_PALETTE[245..247]`，供载入画面与游戏内菜单用 | `sdt_apply_excolors()` |

挂点分布（主线 `fw/src/menu.c`）：`menu_init` 里 `sdtheme_load()` 必须在 `reload_theme()` **之前**；`reload_theme()` 末尾调 `sdtheme_apply_theme()`；`menu_render` 每帧调 `sdtheme_set_page()` + `sdtheme_poll()` + `sdtheme_render_wall()`；补丁库写入后调 `sdtheme_invalidate()`。

## 6. 模块 E：分支固件 superfw-fix（`ref/superfw-fix/`）

在上游 `moribaka/superfw-fix` r75 基础上做 chis（SuperCard）定制，**源码编译**而非烘焙。相对主线多出：

| 特色 | 作用 | 核心文件 |
|---|---|---|
| 菜单压缩重写 | 把菜单内核压进更小空间，腾出 EWRAM | `menu_overlay_*.S/.c`、`menu_code_unpack.S`、`menu_compact_config.h`、`menu_layout*.c/h` |
| SNES 支持 | 用 Snezziboy 核心直接跑 SFC ROM，做 LoROM/HiROM 映射与核心装载 | `sfc.c/h`、`sfc_core_layout.h` |
| 软件 RTC | 没有硬件 RTC 也能给游戏提供时钟，按 ROM 哈希做身份匹配 | `rtc_custom.c/h`、`rtc_state.c`、`rtc_speed.h` |
| ROM 兼容修复 | 自动修 GBA 头校验和、恢复 EEPROM/SRAM/Flash 容量与存档身份 | `romcompat.c/h`、`rom_eeprom_capacity.h` |
| 金手指缓存 | 补丁/作弊结果按 ROM 哈希缓存到 SD，下次直接命中（内置库 1428 条） | `hackpatch.c/h` |
| 等待周期扫描 | 反汇编扫描 ROM 里对 IO 寄存器的写，自动判定等待周期补丁点 | `waitscan.c/h`、`scan_read.h`、`scan_index.h` |
| 中断/VBlank 桥 | 让 overlay 内核接管中断与帧同步 | `irqpatch.c/h`、`vblank_bridge.S/.h` |
| NOR 分散装载 | 游戏内菜单在 NOR 上的分散布局 | `ingame_nor_scatter.S`、`menu_nor_offsets.h` |
| **SD 主题** | 同一套 `sdtheme.c/h`（缓存地址与读缓冲不同） | `sdtheme.c/h` |

构建与校验：

- 构建：`bash ref/superfw-fix/build_chis.sh [SDTHEME_DIAG=1]`
- 自检：`python tools/verify_sffix_port.py`（49 项，含「去掉注释后 `sdtheme.c` 只差缓存地址/读缓冲」的防漂移总闸）
- 版本标识：固件头 `0x0C8` 小端 u32 = `0x75000001`（r75）/ `0x78000001`（r78）；关于页第三行带 `Chis SDT YYYY-MM-DD` 标记以区分官方件与改版

| 界面写「可撤回」但**没有撤销栈** | 只有单步的「重新裁剪」 | `App.clear_page_walls()` 等 |
| 三个**破坏性操作无确认** | 选新壁纸会静默清掉本套 7 张页面图；整套复制图标；整套重置图标 | `pick_wall()` / `copy_icons()` / `reset_icons()` |
| 小屏幕窗口被裁 | 窗口与预览固定尺寸（预览 480×320），无 DPI awareness，1366×768 下底部按钮不可见 | `App.__init__` |
| **固件点阵字库缺字静默留白** | `gbafont.cell()` 缺字返回空 mask 不报错，预览里会莫名缺字 | `app/gbafont.py` |

### 8.3 P2 — 健壮性与细节

- 「另存为」不强制 `.bin` 后缀；保存非原子（中途失败会毁掉原文件）。
- 裁剪对话框的缩放滑块不还原；从 `theme.bin` 打开后裁剪功能被永久禁用且无解释。
- `_fingerprint()` / `has_unsaved()` 有副作用，异常时静默放行 —— 可能丢未保存修改。
- 缺少「把这张图铺给全部 6 套」的一键操作（配色的复制也没有）。
- 没有「机器当前正用第几套」的提示；「整套」这个词在界面上有歧义。
- 编辑时不提示对比度，也不提示「你的颜色已超出 RGB555 精度，真机会掉色」。
- Logo/整屏色对话框即时生效、没有取消按钮。
- 图标缩放用 LANCZOS，边缘会出灰边（真机上是硬边）。
- `to_bytes()` 把图标编码了两次；版本判定逻辑存在两处重复实现。
- **三个独立的版本号来源**：`app/sdedit.py` 的 `APP_VER`、`tools/build_sdedit_exe.py` 的 `NAME`、`app/version.py` 的 `VERSION`（还停在 0.17，属于旧烘焙编辑器那条线）。`bump_version.py` 只改最后一个 → 发新版容易漏改。

### 8.4 P3 — 体验缺口

无 Ctrl+O/S/Z 快捷键、无最近文件、打开文件后强制回第 1 套、多屏 `center_on()` 定位不准、不能导出预览 PNG。

### 8.5 数据与设计层面

- **`dist/v0.30/theme.bin` 是演示包**，不是可直接用的成品：壁纸写着 "SET n / v6 demo"，6 套同一配色公式，正文对比度 17:1 但**选中行只有 2.7~3.9** —— 真机上「一选中那行反而糊」。
- **v6 只有 v0.30+ 固件能读**，老固件按长度整份拒绝并退回内置皮肤（这是设计上的降级，但用户会以为「主题没生效」）。
- 固件菜单布局是**编译期硬编码**（行高 `(1+i)*16`、图标 `x=2`、文字 `x=20`、底栏固定 16px）。编辑器能做到的自由度上限就是「区域 → 颜色角色 / 图片槽」的映射，**布局不可拖**。这是固件限制，不是编辑器的 bug。详见 `docs/fw-integration-review.md`。

### 8.6 发布与验证层面

- **r78 分支固件完整适配已打好但未发布**：`archive/2026-10-22/out/r78-theme-2026-10-22/`（`0x78000001`，自检 50 项 + 两镜像各 13 项全过）。但**上游 r78 本身仍是测试固件，完整实机验收没做**。当前发布基线仍是 r75。
- **测试覆盖不到的地方**：真机显示效果、真实 SD 卡读取时序、GUI 交互（只能靠 PrintWindow 截图人工比对）。所有自检都只验结构，不能代替实机。
- 游戏内菜单那 5 个图标两个固件都**不支持替换**（编译在压缩 payload 里，无运行时覆盖指针）。这是已确认的能力边界，不是待办。
