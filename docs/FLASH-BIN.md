# 用外部烧录器写 SuperFW-Fix（.bin 路线）

内置「固件升级」只认 `.fw`（要求 `header->fw_size == 文件大小`）。有烧录器可以直接写 NOR
裸片，走这份流程。

---

## 0. 先确认三件事（后面怎么写取决于它们）

| 要确认的 | 从哪看 | 为什么重要 |
| --- | --- | --- |
| NOR 容量 | 开机进「烧录 / Flash」页面，CFI 会显示 size 与 block size | 决定镜像是 2 MiB 还是 4 MiB |
| 芯片封装 / 型号 | 拆机看丝印，或烧录器自动识别 | 决定夹子、适配座、时序 |
| CPLD 是否在位 | 板上是否直连 NOR | 在位时可能干扰总线，一般需要复位或断开 |

固件里的分区是写死的（`src/common.h`）：

```
0x000000 .. 0x200000   固件区（ROM_OFF_FLAHFIRMW = 0，最大 2 MiB）
0x200000 .. 0x400000   元数据区（ROM_OFF_FLASHMETA，FLASH_METADATA_SIZE = 0x200000）
```

也就是说**芯片至少 4 MiB**，固件只占前 2 MiB。元数据区存「最近使用 / NOR 游戏列表」，
擦掉不影响启动（`flashmgr_load()` 失败会清零重建），但每次开机都要重扫，第一屏会慢几秒。

---

## 1. 动手前必须做的两件事

1. **读回整片备份**（至少 4 MiB），存两份，各算一次 sha256。
   出问题这是唯一能把你救回原状的东西。
2. **空白检查**：确认擦除态是 `0xFF`。不是 `0xFF` 说明烧录器电压/时序设置不对，
   先别写。

---

## 2. 生成镜像

```bash
# A. 只写固件区（2 MiB）—— 推荐，元数据区不碰
.venv314/Scripts/python.exe tools/make_flash_bin.py \
    dist/superfw-fix/SuperFW-Fix-Chis-SDTheme.fw \
    -o out/sffix-local/superfw-fix-2m.bin

# B. 整片镜像（烧录器只收整片时）—— 用备份当底，保住元数据区
.venv314/Scripts/python.exe tools/make_flash_bin.py \
    dist/superfw-fix/SuperFW-Fix-Chis-SDTheme.fw \
    --base dump.bin --size 0x400000 -o out/full.bin
```

脚本会先自检输入（`fw_size` / 游戏名 / 头部 sha256），再补 `0xFF` 到目标大小，最后回读校验。

**不改任何头部字段** —— `fw_size` 仍然是 1,969,664，不是 0x200000。补 `FF` 只是把
内置升级器「擦除后留下的空尾」复现出来，两者写出来的 NOR 内容是一样的。

---

## 3. 烧录顺序

1. 空白检查（Blank Check）
2. 擦除：按扇区擦（1 MiB 的块不要用，扇区擦更稳）
3. 写入：从**偏移 0x000000** 开始，长度 2,097,152 字节
4. 校验：读回 + 逐字节比较（一定要做，别只看烧录器自报 OK）
5. 断电、装卡、上电

---

## 4. 关键确认点

| 检查项 | 正确值 | 写错的后果 |
| --- | --- | --- |
| 起始偏移 | `0x000000` | 偏移错了 → 上电直接白屏/黑屏，GBA 找不到 ROM 头 |
| 写入长度 | `2,097,152`（2 MiB） | 少写 → 固件被截断，跑到一半崩 |
| 填充字节 | `0xFF` | 填 `0x00` → 擦除态不匹配，后续升级会校验失败 |
| 头部 `fw_size`（0xCC） | `1,969,664` | 改成 0x200000 → 内置升级器从此拒绝所有 `.fw` |
| 元数据区 0x200000 | 不写固件数据 | 写了 → 最近列表/游戏库混乱 |
| 文件扩展名 | `.bin` 只给烧录器，`.fw` 只给内置升级器 | 混用 → 升级器报「文件过大」或直接不认 |

---

## 5. 首次上电怎么算成功

1. 能进菜单（说明固件区和 GBA 头都对）
2. 进「烧录」页面，NOR 信息正常显示，不是 `No CFI`
3. 卡里自动出现 `/.superfw/theme.bin`（26,680 B）→ SD 主题链路通
4. 把演示包改名 `theme.bin` 覆盖进去，重启 → 6 套配色 / 壁纸 / Logo 全换

## 6. 失败判据

| 现象 | 判断 |
| --- | --- |
| 上电全白或全黑，进不去菜单 | 偏移错 / 长度不够 / 没擦干净 |
| 菜单能起，但「最近使用」空的 | 正常（元数据区被擦），重扫一次就好 |
| 显示 `No CFI (hardwired 2048KiB)` | 芯片没被识别，检查是否写坏配置区或接线 |
| 菜单出来了但主题不变 | 刷诊断版看底部四行字，别猜 |
