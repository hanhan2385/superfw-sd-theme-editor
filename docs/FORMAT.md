# theme.bin 格式

小端，字段按 4 字节对齐。放在 SD 卡的 `/.superfw/theme.bin`（也认 `/superfw/theme.bin` 和根目录 `/theme.bin`）。

```
0x0000  char[8]   "SFWTHM01"
0x0008  u16       版本 1 / 2 / 3
0x000A  u16       标志位
                    v1: bit0      = 带壁纸（6 套共用一张）
                    v2: bit(1+i)  = 第 i 套有自己的壁纸
                    v3: bit(7+p)  = 第 p 个页面有自己的壁纸
0x000C  u32       文件长度
0x0010  u16[36]   6 套 × 6 个 RGB555（顺序：FG, BG, FT, HI, HIB, SH）
0x0058  u8[6*4432]  6 套图标，每套 = 4352 B 精灵 + 38 项调色板（76 B）+ 4 B 对齐
0x6838  壁纸段，每段 35000 B = 34560 索引（240×144）+ 220 项调色板
```

## v4：每套 × 每页（42 槽）

v3 的 7 张页面图是**全局**的（6 套共用）。v4 在 v3 之后再加一层「哪一套的哪一页」：

```
0x0000..0x7598F 和 v3 完全一样（含那 7 张全局页图，留作兜底）
0x75990  u32 × 2    42 位掩码，bit(set*7+page) = 这一套这一页有自己的图
0x75998  u8[42*35000]  6 套 × 7 页，定长连排，空槽也占 35000 B（全 0）
```

总长固定 **1,951,688 B**。取图优先级：

```
(套,页) 专属图 → 全局页图（v3）→ 该套主题图 → BG 纯色
```

掩码位序 = `set * 7 + page`，固件 `sdt_has_page_set()` 与 Python `slot_index()` 必须一致。

**导出时自动降级**：编辑器里如果某一页在 6 套中完全一样，会合并回 v3 的全局段；
只有当至少一套不同（或有套没图）时，这一页才进 v4。所以只要不碰「按套页面图」，
产出的文件仍然是 v1/v2/v3，老固件照样能读。

v4 只有 v0.23 起的固件认识，老固件读到版本号 4 会整份跳过（回落内置皮肤，不会崩）。

## v5 / v6 / v7：在 v4 后面追加的尾巴

v5 起不再动前面的大块，只在**文件末尾**追加定长尾巴，版本号跟着尾巴走：

| 版本 | 尾巴 | 内容 |
|---|---|---|
| v5 | 36 B | 6 套 × 3 个 RGB555：载入画面底 / 载入进度条 / 游戏内菜单底 |
| v6 | 259 B | 上面 36 B + logo（31×7 = 217 B 索引 + 3 个 RGB555 = 6 B） |
| v7 | 271 B | 上面 259 B + 6 套 × 2 B 界面透明度（`[底栏, 选中条]`，0..16，0 = 实心） |

常量（两边必须一致，`tools/test_sdtheme_pack.py` 会解析 `#define` 对账）：
`EXCOL_BYTES=36`、`V6_TAIL=259`、`ALPHA_BYTES=12`、`V7_TAIL=271`。

**两个坑**：

- 固件看到 `b[8] >= 6` 就去读 logo 段。所以写 v7 时**即使没设 logo 也必须补一份**
  （编辑器用 `builtin_logo()` 兜底），否则关于页 logo 是它后面那 12 字节透明度。
- **全 0 的透明度不写**：6 套 12 个值全 0 时保持 v5/v6，老固件照读。
  一旦写了 v7，老固件（不认版本 7）会整份跳过 → 壁纸退回纯色。

## 版本自动挑选

| 内容 | 版本 | 大小 |
|---|---|---|
| 没有壁纸 | v1 | 26,680 B |
| 6 套同一张 | v1 | 61,680 B（老固件也能读） |
| 每套各一张 | v2 | 236,680 B |
| 有任何页面图 | v3 | 481,680 B |
| 有界面透明度（v7 尾巴） | v7 | 基础 + 271 B |
| 有选中条纹理 | v8 | 基础 + 1,993 B |

## 几个容易踩的点

- **壁纸索引是调色板槽号 20..239**，不是从 0 开始。写自己的工具时必须按槽号取色，
  写成 `pal[idx-1]` 会让整套配色错位一格。
- 图标调色板第 0 项恒为透明，颜色写在 1..37。
- v3 文件在有页面图时，壁纸段是 7 段连排（v2 的 6 段之后），偏移 `0x39CC8` 起。
- 取图优先级：**页面图 > 当前套的主题图 > 纯色**。所以切主题时，配了专属图的页面不会变。

格式的权威定义在 `fw/src/sdtheme.h`，Python 侧实现在 `app/sdtheme.py`，两边的常量由
`tools/test_sdtheme_pack.py` 解析 `#define` 做对照，改一处必须同步另一处。

## v8：选中条纹理（16×16）

排在 v7 那 271 字节之后，每套**定长 287 字节**，六套连排：

| 偏移 | 长度 | 内容 |
|---|---|---|
| +0 | 1 | 色数 n（0..15，0 = 这套没有纹理） |
| +1 | 30 | 15 个 RGB555（只前 n 个有效，其余写 0） |
| +31 | 256 | 16×16 的 8bpp 像素，值 0..n |

- `V8_TAIL = 271 + 6×287 = 1993`。固件按 `fsz - V8_TAIL + 271 + set*287` 寻址。
- **像素值 0 = 自动色**，固件渲染时映射到 OBJ 调色板的 **240 号槽**，而 240 号写的是
  本套的 `hi_blend` → 换套自动变色。1..n 映射到 241..255。
- OBJ 调色板 0..37 归图标（`SDT_ICON_PALN = 38`），38..239 空着，240..255 归选中条。
- **没有透明像素**：tile 里 0 也是实色。透明会露出壁纸，文件名就读不出来。
- 六套都没有纹理就不写，文件保持 v7 或更老；一旦写了 v8，老固件整份跳过
  → 升级顺序必须是**先刷固件、再放 theme.bin**。
- 横向必然 16 像素一循环（真机是 63 号 OBJ 精灵铺 15 次），纵向 16 行可任意画。
