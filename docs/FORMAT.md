# theme.bin 格式

小端，字段按 4 字节对齐。放在 SD 卡的 `/.superfw/theme.bin`（也认 `/superfw/theme.bin` 和根目录 `/theme.bin`）。

```
0x0000  char[8]   "SFWTHM01"
0x0008  u16       版本 1 / 2 / 3
0x000A  u16       标志位
                    v1: bit0      = 带壁纸（6 套共用一张）
                    v2: bit(1+i)  = 第 i 套有自己的壁纸
                    v3: bit(7+p)  = 第 p 个页面有自己的壁纸
0x000C  u32       文件长度
0x0010  u16[36]   6 套 × 6 个 RGB555（顺序：FG, BG, FT, HI, HIB, SH）
0x0058  u8[6*4432]  6 套图标，每套 = 4352 B 精灵 + 38 项调色板（76 B）+ 4 B 对齐
0x6838  壁纸段，每段 35000 B = 34560 索引（240×144）+ 220 项调色板
```

## v4：每套 × 每页（42 槽）

v3 的 7 张页面图是**全局**的（6 套共用）。v4 在 v3 之后再加一层「哪一套的哪一页」：

```
0x0000..0x7598F 和 v3 完全一样（含那 7 张全局页图，留作兜底）
0x75990  u32 × 2    42 位掩码，bit(set*7+page) = 这一套这一页有自己的图
0x75998  u8[42*35000]  6 套 × 7 页，定长连排，空槽也占 35000 B（全 0）
```

总长固定 **1,951,688 B**。取图优先级：

```
(套,页) 专属图 → 全局页图（v3）→ 该套主题图 → BG 纯色
```

掩码位序 = `set * 7 + page`，固件 `sdt_has_page_set()` 与 Python `slot_index()` 必须一致。

**导出时自动降级**：编辑器里如果某一页在 6 套中完全一样，会合并回 v3 的全局段；
只有当至少一套不同（或有套没图）时，这一页才进 v4。所以只要不碰「按套页面图」，
产出的文件仍然是 v1/v2/v3，老固件照样能读。

v4 只有 v0.23 起的固件认识，老固件读到版本号 4 会整份跳过（回落内置皮肤，不会崩）。

## 版本自动挑选

| 内容 | 版本 | 大小 |
|---|---|---|
| 没有壁纸 | v1 | 26,680 B |
| 6 套同一张 | v1 | 61,680 B（老固件也能读） |
| 每套各一张 | v2 | 236,680 B |
| 有任何页面图 | v3 | 481,680 B |

## 几个容易踩的点

- **壁纸索引是调色板槽号 20..239**，不是从 0 开始。写自己的工具时必须按槽号取色，
  写成 `pal[idx-1]` 会让整套配色错位一格。
- 图标调色板第 0 项恒为透明，颜色写在 1..37。
- v3 文件在有页面图时，壁纸段是 7 段连排（v2 的 6 段之后），偏移 `0x39CC8` 起。
- 取图优先级：**页面图 > 当前套的主题图 > 纯色**。所以切主题时，配了专属图的页面不会变。

格式的权威定义在 `fw/src/sdtheme.h`，Python 侧实现在 `app/sdtheme.py`，两边的常量由
`tools/test_sdtheme_pack.py` 解析 `#define` 做对照，改一处必须同步另一处。
